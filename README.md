## 🚀 2. Ключевые возможности сайта

1. **AI-Автоконсультант 24/7 (`AiAutoConsultant`):**
   - **Главная модель по умолчанию (Платная):** **`minimax/minimax-m3`** — платная флагманская модель MiniMax: сверхбыстрый отклик, глубокое понимание автомобильных каталогов. **Для неё рассчитывается и выводится точный расход токенов и ориентировочная стоимость в USD и рублях** (`usage.total_tokens` и `usage.cost`).
   - **Бесплатные модели OpenRouter ($0 / 0 токенов списания):**
     1. `openrouter/free` — 🌟 Free Router (Автоматический подбор свободной модели)
     2. `inclusionai/ling-3.0-flash-sante:free` — ⚡ Ling 3.0 Flash (256k контекст)
     3. `dots-studio/dots-3-note-preview:free` — 📝 Dots 3 Note Preview (512k контекст)
     4. `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free` — 🧠 NVIDIA Nemotron 3 Nano
     5. `liquid/lfm-2.5-2.6b:free` — 💧 Liquid LFM 2.5
     *(Для бесплатных моделей подсчёт расхода токенов и стоимости намеренно скрыт, отображается статус «Бесплатная модель OpenRouter (0 токенов)»).*
   - **Сессионный контекст диалога и автосброс после 10 сообщений:**
     - Для каждого пользователя в базе данных Supabase создаётся активная сессия (`chat_sessions`).
     - Вся история переписки (вопросы клиента и ответы ассистента) сохраняется в хронологическом порядке в `chat_messages`.
     - **Удержание контекста и память авто:** ИИ помнит марку, год, двигатель и ранее названные поломки авто на протяжении всей сессии. При уточняющих вопросах ИИ не здоровается заново («Здравствуйте!»), а естественно развивает диалог.
     - **Автоматический сброс после 10 запросов:** сессия строго удерживает до 10 запросов пользователя. На 11-м запросе завершенная сессия автоматически переводится в `status = 'completed'`, создается чистая новая сессия, а счётчик контекста в шапке чата сбрасывается обратно в `1/10`.
     - Также пользователь может в любой момент сбросить сессию вручную кнопкой «Обновить сессию» (иконка со стрелкой).
   - **Скрипт и шаблон продажи с ценой и временем (`SALES_BOOKING_SCRIPT`):**
     - Называет конкретные цены на запчасти (оригинал / проверенный аналог со склада на ул. Печёнкина, 1а) и стоимость работ (замена стойки 1 500 ₽, прокачка стоек от 1 500 ₽, замена колодок от 1 200 ₽, диагностика бесплатно при ремонте).
     - Предлагает 2 конкретных свободных слота времени (например: *сегодня в 16:30* или *завтра в 11:00* с 10:00 до 20:00).
     - Выводит строгий шаблон подтверждения записи и формирует кнопки быстрых ответов в 1 клик.
   - **Умные каскадные фоллбэки (Fallback Chain):** в запросе передается массив `models` (до 3 моделей по спецификации OpenRouter), благодаря чему при сбое или исчерпании лимита модель мгновенно заменяется следующей без задержки.
   - **Защита от утечки ошибок на сайт:** технические коды ошибок (400, 403, 429, 500) **никогда не выводятся посетителю**. Пользователь видит вежливое сообщение от лица сервиса с предложением набрать мастера или оставить номер.
   - **Ярко выраженные логи ошибок (`openrouter_errors.log`):** все сбои провайдеров логируются в консоли терминала в виде заметных рамок с таймштампом и сохраняются в файл `openrouter_errors.log`.

2. **Система фиксации заявок и почтовых уведомлений (`mailer.ts`):**
   - Автоматически распознает номер телефона и имя клиента в диалоге с AI.
   - Отправляет структурированное письмо с полной историей переписки на почту администратора/мастера (`NOTIFICATION_EMAIL`).
   - Работает в двух режимах:
     - **Тестовый/Резервный:** записывает заявки с таймштампом в файл `leads_mail_log.txt`.
     - **Боевой SMTP:** отправляет через защищенное TLS-соединение почтового провайдера (Mail.ru, Yandex, VK WorkMail).

3. **База данных Supabase (`supabase/schema.sql`):**
   - **Таблица лидов и бронирования (`service_leads`):** автоматическая фиксация заявок клиентов в ходе AI-диалога. Поля: `phone`, `telegram` (@username для последующего подтверждения автоботом), `car`, `service_requested`, `preferred_time`, `status` (`new`, `pending_tg_bot`, `confirmed`, `completed`).
   - При получении контактов AI-ассистент подтверждает запись («✅ Все данные успешно записаны и зафиксированы в базе автосервиса!») и предлагает оставить Telegram для получения талона брони от бота.
   - Хранение сессий пользователей (`chat_sessions`) и сообщений (`chat_messages`).
   - Хранимая SQL-процедура `get_session_context(p_session_id, p_limit)` для выборки сообщений.
   - Если переменные Supabase не заданы — система прозрачно переключается на встроенное хранилище сессий в памяти (In-Memory Fallback).

4. **Адаптивный дизайн и темы оформления:**
   - **Переключатель тем (Светлая / Тёмная):** кнопка в хедере с запоминанием выбора в `localStorage`.
   - **Контрастные блоки:** стильные белые карточки с четким черным шрифтом внутри темной темы (`--card-white`).
   - **Компактные иконки соцсетей:** аккуратные плашки Telegram и ВКонтакте.
   - **Фиксированное меню:** предотвращен нежелательный перенос пункта «О нас».
   - **Интерактивные карты (`InteractiveMap`):** Яндекс.Карты с быстрым переключением на Google Карты и кнопками навигатора (Яндекс Карты, Google, 2ГИС).

## 🛠 3. Настройка окружения (`.env.local`)

Создайте или отредактируйте файл `.env.local` в корне проекта:

```ini
# ==========================================
# 1. OpenRouter AI API (Обязательно для AI-чата)
# ==========================================
OPENROUTER_API_KEY=sk-or-v1-ваш-ключ-openrouter

# ==========================================
# 2. Уведомления о лидах на почту
# ==========================================
NOTIFICATION_EMAIL=info@autobox74.ru

# Для реальной отправки писем через SMTP (Mail.ru):
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=ваш_ящик@mail.ru
SMTP_PASS=пароль_для_внешних_приложений
SMTP_FROM="AutoBox74 Автосервис" <ваш_ящик@mail.ru>

# (Если SMTP не настроен, заявки надежно логируются в leads_mail_log.txt)

# ==========================================
# 3. Supabase (Опционально для постоянного хранения)
# ==========================================
NEXT_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=ваш-anon-key
SUPABASE_SERVICE_ROLE_KEY=ваш-service-role-key
```

### 📧 Как настроить отправку через Mail.ru:
1. Зайдите в ваш почтовый ящик Mail.ru -> **Настройки** -> **Безопасность** -> **Пароли для внешних приложений**.
2. Создайте пароль, назовите его, например, `autobox-bot`.
3. Скопируйте полученный 16-значный пароль в переменную `SMTP_PASS`.
4. В `SMTP_USER` и `SMTP_FROM` укажите ваш адрес на Mail.ru.

## 📦 4. Инициализация базы данных Supabase

Вы можете настроить Supabase **в 1 команду через один Access Token**:

### Вариант А: Автоматически через один Access Token (Рекомендуется)
1. Получите Personal Access Token в личном кабинете: [supabase.com/dashboard/account/tokens](https://supabase.com/dashboard/account/tokens) (нажмите *Generate new token*).
2. Запустите команду:
```bash
npm run setup:supabase sbp_ваш_токен
```
Скрипт автоматически:
- Определит ваш проект в Supabase;
- Скачает и запишет в `.env.local` все URL и API-ключи;
- Применит SQL-схему `supabase/schema.sql` (создаст таблицы `chat_sessions`, `chat_messages` и функцию контекста).

### Вариант Б: Вручную через переменные в `.env.local`
1. Скопируйте `Project URL`, `anon` и `service_role` ключи из раздела *Project Settings -> API*.
2. Вставьте их в `.env.local`:
```ini
NEXT_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=ваш-anon-key
SUPABASE_SERVICE_ROLE_KEY=ваш-service-role-key
```
3. Откройте панель [Supabase Dashboard -> SQL Editor](https://supabase.com/dashboard), скопируйте и выполните содержимое [`supabase/schema.sql`](supabase/schema.sql).

## 🧠 5. Системный промпт автоконсультанта и скрипт продаж

Все системные промпты, инструкции поведения ИИ и сценарии закрытия на запись хранятся **в одном центральном файле конфигурации**:
👉 [`src/config/ai.config.ts`](src/config/ai.config.ts)

### Ключевые переменные в `src/config/ai.config.ts`:
1. **`AI_SYSTEM_PROMPT`** (`AUTOBOX_SYSTEM_PROMPT`) — главный системный промпт, задающий роль старшего мастера-приёмщика на ул. Печёнкина, 1а, проверку по автомобильным каталогам, запрет на черновики и английский язык.
2. **`SALES_BOOKING_SCRIPT`** — строгий скрипт продажи услуг с фиксированными ценами на работы, предложением 2 конкретных слотов времени и закрытием на запись.
3. **`CONFIGURED_OPENROUTER_MODELS`** — реестр моделей с OpenRouter (`minimax/minimax-m3` по умолчанию, бесплатные модели и альтернативы).
4. **`SESSION_SETTINGS`** — лимит контекста (10 сообщений на сессию) и адресные данные автосервиса.

### Стандарты выдачи и чистоты сообщений (БЕЗ текстовой графики):
- **Полный запрет на текстовую графику и разделители:**
  - Запрещены любые псевдографические разделительные линии (`---`, `===`, `___`, `***`).
  - Запрещены псевдографические и markdown-таблицы (`|---|---|`, `+---+---+`), так как на узких экранах смартфонов они ломаются и требуют неудобной горизонтальной прокрутки.
  - Все детали и работы перечисляются аккуратными маркированными строками (например: `• Замена стойки — 1 500 ₽`).
- **Собранность и легкая читаемость:**
  - Сообщение должно быть собранным и читаться за 10–15 секунд с любого смартфона.
  - Четкое разделение: стоимость запчастей (оригинал / проверенный аналог) отделена от стоимости работ.
  - Обязательный оффер: бесплатная диагностика ходовой при ремонте, гарантия до 1 года, детали на складе на ул. Печёнкина, 1а.
  - Конкретные слоты времени (например, сегодня в 16:30 или завтра в 11:00).
- **Двойная гарантия чистоты:**
  1. **На уровне промпта:** строгие запреты прописаны в системной инструкции модели.
  2. **На уровне кода:** в `src/lib/openrouter.ts` встроен фильтр, который автоматически конвертирует любые таблицы в маркированные списки и удаляет разделители.

Полное руководство по развертыванию, защите сервера (UFW, Fail2ban), настройке SSL Let's Encrypt и Rate Limiting Nginx находится в файле 👉 [`VPS_DEPLOYMENT_GUIDE.md`](VPS_DEPLOYMENT_GUIDE.md).

### Краткий Fast-Track запуск на чистом сервере:

```bash
# 1. Клонируйте проект под пользователем deployer:
git clone https://github.com/ВАШ_АККАУНТ/autobox.ru.git /home/deployer/autobox.ru
cd /home/deployer/autobox.ru
mkdir -p certbot/conf certbot/www

# 2. Создайте боевой конфиг .env.local:
cp .env.example .env.local
nano .env.local

# 3. Выпустите бесплатный SSL-сертификат через Certbot (DNS уже настроен на IP):
docker run -it --rm -p 80:80 \
  -v "$(pwd)/certbot/conf:/etc/letsencrypt" \
  -v "$(pwd)/certbot/www:/var/www/certbot" \
  certbot/certbot certonly --standalone \
  -d autobox74.ru -d www.autobox74.ru \
  --email info@autobox74.ru --agree-tos --no-eff-email

# 4. Запустите стек сервисов (Next.js + Nginx + Certbot Auto-Renew):
docker compose up -d --build

# 5. Проверьте статус контейнеров:
docker compose ps
```

## 🐛 9. Исправленные критические баги

### Потеря контекста диалога и повторяющиеся ответы (05.10.2026)

**Проблема:**
1. AI-бот повторял одно и то же общее сообщение со списком услуг (1️⃣ Подвеска 2️⃣ Тормоза...), даже когда клиент задавал конкретный вопрос («нужно поменять свечи сколько будет стоить?»).
2. На следующем вопросе бот забывал автомобиль («Подскажите, пожалуйста, марку, модель и год выпуска...»).
3. В базе данных Supabase накапливались дубликаты активных сессий, которые не закрывались.

**Корневые причины:**
1. **CHECK Constraint в Supabase:** в таблице `chat_sessions` ограничение `chat_sessions_status_check` не принимало статус `'completed'` (допускались только `'active'`, `'closed'`). Запрос на закрытие сессии завершался ошибкой PostgreSQL `23514`, и старая сессия оставалась активной, параллельно создавая новую пустую.
2. **Амнезия при сбросе (Hard Wipe):** при достижении 10 сообщений код возвращал `history: []` (полное обнуление истории диалога). Из-за этого на 11-м запросе ИИ получал пустой контекст и снова спрашивал марку машины.
3. **Отсутствие долговременной памяти автомобиля:** марка авто жила только внутри реплик пользователя. Если реплика уходила за границу окна, модель теряла данные об автомобиле.
4. **Повторение шаблонов:** при отсутствии четкого запрета в промпте на общие меню при конкретных вопросах модель повторяла ранее выданный список услуг.

**Что реализовано и исправлено:**
1. **База данных Supabase:**
   - Ограничение `chat_sessions_status_check` обновлено через Supabase API: теперь поддерживаются `'active'`, `'closed'`, `'completed'`, `'lead_captured'`.
   - Закрыты все «подвисшие» дубликаты сессий.
2. **Архитектура скользящего окна (Sliding Window):**
   - Вместо внезапного обнуления контекста реализовано скользящее окно последних диалоговых реплик (`sessionMsgs.slice(-20)`). Сообщения накапливаются в Supabase, а ИИ всегда видит актуальные предыдущие шаги диалога.
3. **Постоянная память автомобиля (`chat_sessions.client_car`):**
   - Реализована функция `extractCarInfo(text)`: при упоминании автомобиля (Honda, Toyota, ВАЗ, Kia и т.д.) марка/модель автоматически сохраняются в колонку `client_car` сессии.
   - В контекст каждого запроса внедряется системный блок `ПАМЯТЬ АВТОСЕРВИСА О КЛИЕНТЕ`: модель **жестко знает автомобиль клиента** и никогда не переспрашивает его, даже если диалог идет долго.
   - В шапке чата на сайте выводится индикатор: `Контекст: 2/10 • 🚗 Toyota Camry 2.5 2018`.
4. **Системный промпт (`src/config/ai.config.ts`):**
   - Добавлено правило №6: категорический запрет на выдачу общих меню-списков при конкретном вопросе клиента.

## 🔒 10. Комплексная безопасность и защита AI-чата от спам-атак и слива токенов

В проект внедрена многоуровневая система защиты (**Defense-in-Depth**) для предотвращения несанкционированного расхода баланса OpenRouter при включении платных флагманских моделей (например, `minimax/minimax-m3`).

### 🛡️ 1. Архитектура защиты от накрутки токенов (`src/lib/rate-limit.ts`)

| Уровень защиты | Механизм | Поведение при нарушении |
| :--- | :--- | :--- |
| **Кулдаун между сообщениями** | Таймер 5 секунд (`CHAT_COOLDOWN_SECONDS`) | Возврат HTTP 429 (`waitTimeSeconds: 5`), на кнопке отправки тикает обратный отсчёт `5s...` |
| **Ограничение длины вопроса** | Максимум 600 символов (`CHAT_MAX_MESSAGE_LENGTH`) | HTML `maxLength={600}` на клиенте + HTTP 400 на сервере («Вопрос слишком длинный») |
| **Circuit Breaker (Суточный лимит)** | 100 платных ответов в день на весь сервис (`CHAT_DAILY_PAID_LIMIT`) | При исчерпании 100 ответов сервер **автоматически переключает модель на бесплатную** `openrouter/free` ($0), не блокируя клиентов |
| **Квота платных сессий на IP** | 2 платные сессии в сутки на один IP (`CHAT_PAID_SESSIONS_PER_DAY`) | Начиная с 3-й сессии за день данный IP прозрачно переводится на бесплатную модель `openrouter/free` |
| **Частотный лимит IP (Минута)** | 6 запросов в минуту (`CHAT_IP_MAX_REQUESTS_PER_MINUTE`) | HTTP 429 («Слишком частые запросы. Подождите 30 секунд.») |
| **Частотный лимит IP (Час)** | 40 запросов в час (`CHAT_IP_MAX_REQUESTS_PER_HOUR`) | HTTP 429 («Превышен часовой лимит. Позвоните мастеру: +7 (995) 927-77-54») |
| **Honeypot-ловушка ботов** | Скрытое поле `bot_trap_field` (скрыто через `aria-hidden`, `tabIndex={-1}`, `opacity-0`) | Парсеры и спам-боты заполняют поле → сервер **мгновенно возвращает дежурный ответ 200 OK без вызова LLM** (0 списанных токенов!) |
| **Nginx Rate Limiting** | `limit_req_zone $binary_remote_addr zone=chat_limit:10m rate=10r/m;` | Аппаратный отсев DDoS на сетевом шлюзе с возвратом HTTP 429 до попадания в Node.js runtime |

### ⚙️ 2. Конфигурация через переменные окружения (`.env.local`)

Все числовые значения вынесены в переменные окружения и могут легко меняться без изменения кода:

```ini
# ==========================================
# AI CHAT ANTI-SPAM & TOKEN PROTECTION
# ==========================================
# Кулдаун между отправкой сообщений (сек)
CHAT_COOLDOWN_SECONDS=5

# Максимальная длина одного сообщения клиента (символов)
CHAT_MAX_MESSAGE_LENGTH=600

# Общий лимит вызовов платных моделей в день на весь сервис (Circuit Breaker)
CHAT_DAILY_PAID_LIMIT=100

# Лимит уникальных сессий с платной моделью на один IP в сутки (далее fallback на openrouter/free)
CHAT_PAID_SESSIONS_PER_DAY=2

# Максимум запросов к AI-чату в минуту с одного IP
CHAT_IP_MAX_REQUESTS_PER_MINUTE=6

# Максимум запросов к AI-чату в час с одного IP
CHAT_IP_MAX_REQUESTS_PER_HOUR=40
```

### 🧪 3. Результаты тестов верификации безопасности

1. **Тест Honeypot-ловушки:**
   - Запрос: `POST /api/chat` с заполненным полем `bot_trap`.
   - Результат: HTTP 200, мгновенный возврат ответа мастера, вызов OpenRouter API **пропущен**, расход токенов = **0**.
2. **Тест длины сообщения:**
   - Запрос: `POST /api/chat` с текстом >600 символов.
   - Результат: HTTP 400 (`MESSAGE_TOO_LONG`), `Вопрос слишком длинный (605 символов). Максимальная длина — 600 символов`.
3. **Тест кулдауна 5 секунд:**
   - Запрос: повторная отправка через 200 мс после первой.
   - Результат: HTTP 429 (`COOLDOWN`), `Подождите 5 сек. перед отправкой следующего сообщения.`. На фронтенде кнопка блокируется с таймером обратного отсчёта.
4. **Тест защиты баланса (Circuit Breaker):**
   - При превышении суточного лимита 100 запросов или квоты 2 сессий на IP запрос не падает с ошибкой, а перенаправляется на `openrouter/free`. Посетитель получает полноценную консультацию, а баланс владельца автосервиса надежно защищен.

## 🔒 11. Общая серверная безопасность
- Секретные ключи API никогда не попадают в клиентский бандл (вызовы OpenRouter и почты происходят строго в изолированном серверном runtime `Next.js`).
- Контейнеры запускаются под непривилегированным пользователем `nextjs:nodejs` (`UID 1001`).
- Реализованы лимиты запросов (Rate Limiting) в Nginx и автоматический бан ботов через `fail2ban`.
